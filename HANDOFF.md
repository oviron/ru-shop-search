# HANDOFF: плагин поиска товаров по российским магазинам

Документ для агента, который продолжает работу. Читай целиком перед первым действием.
Подробная разведка с матрицей, источниками и механикой антиботов лежит в
[docs/handoff/research-2026-09-27.md](docs/handoff/research-2026-09-27.md).

## Зачем

Дмитрий хочет спросить в Claude Code «где дешевле RTX 5070» или «нормальная ли цена у
этого лота на Авито» и получить ответ по живым ценам нескольких магазинов, со ссылками и
честной оценкой уверенности. Сейчас такого инструмента нет: готовые MCP-серверы либо
покрывают 1–2 магазина, либо ломаются на антиботах, либо тащат лишнее.

Результат: **плагин Claude Code** (`.claude-plugin/plugin.json` с MCP-сервером, `skills/`),
который ставится одной командой и работает с этого мака. Пользователь один. Публикация и
поддержка чужих пользователей не цель.

## Что уже решено

- **База.** Этот репозиторий форкнут из `Vladimir-Human/ru-marketplace-mcp` (MIT, v2.4.2,
  uv workspace, 16 пакетов, ~48k строк Python). Ядро `mcp-core` и часть коннекторов
  оставляем, лишнее вырезаем. Объединённый сервер уже есть: пакет `marketplace-connector`,
  команда `marketplace-mcp`.
- **Магазины, которые должны работать:** WB, Ozon, Яндекс Маркет, DNS, Ситилинк, М.Видео,
  Детский мир, Лэмода, ВсеИнструменты, Regard, Никс, Холодильник, AliExpress, Pepper, Авито.
- **Не делаем:** Эльдорадо (Group-IB), Мегамаркет и OnlineTrade (ServicePipe в браузере
  тоже), Taobao, MPStats, Циан, `dsh/`, Docker и публикацию в MCP-реестр.
- **Три уровня транспорта**, выбирается самый дешёвый рабочий:
  1. HTTP через `curl_cffi` с `impersonate="chrome"`: Маркет, карточка WB, поиск М.Видео
     (`/bff/products`), Детмир, Лэмода, ВсеИнструменты, Regard, Никс, Холодильник.
  2. HTTP с токеном, выданным браузером: WB-поиск (`x_wbaas_token` + `deviceid`).
  3. Браузер как транспорт: `fetch` изнутри вкладки у Ozon, Pepper, AliExpress; у DNS,
     Ситилинка и карточки М.Видео вкладка открывает саму страницу и читает из неё цены
     (почему — в «Отступлениях»).
- **Браузер:** отдельный анонимный постоянный профиль Chrome (`--user-data-dir`, не
  дефолтный профиль Дмитрия: Chrome 136+ туда CDP и не пустит), CDP только на
  `127.0.0.1`. Логина нигде нет и не будет.
- **Сеть:** всё идёт с домашнего резидентного IP, магазины на `.ru` роутер и так пускает
  напрямую. RU VPS только запасной выход для Qrator-магазинов, Маркета и WB-поиска с
  токеном; для ServicePipe и DDoS-Guard он хуже дома. Доступ к VPS:
  `/Users/oviron/cl/projects/vpn/server/ru-relay.md`.
- **Инструменты MCP:** `search`, `card`, `compare`, `price_history`, `avito_evaluate`,
  плюс диагностический `shops` (кто подключён, кто на стопе).
  `compare` сопоставляет товары через `compare-connector/identity.py`: GTIN с контрольной
  суммой, затем бренд + MPN, затем модель, с уровнем уверенности. Цена по подписке в
  ранжирование не идёт. `price_history`: свои снимки в SQLite в `${CLAUDE_PLUGIN_DATA}`
  плюс история WB (basket `price-history.json`) и DNS.
- **Скиллы:** «найди дешевле по N площадкам», «оцени лот на Авито», «честная ли скидка».
  Скиллы апстрима (по одному на коннектор) заменяются этими тремя; что из них полезно,
  перенеси.

## План

Порядок важен: сначала база и обвязка, потом магазины по одному, Авито последним.

1. **Базовая линия.** `uv sync`, затем `uv run pytest -m "not live and not cdp"`,
   `uv run ruff check`, `uv run mypy`. Запиши, что было зелёным до правок, чтобы потом
   отличать свою поломку от унаследованной.
2. **Урезать.** Удалить пакеты `taobao-connector`, `mpstats-connector`, `cian-connector`,
   `megamarket-connector`, каталоги `dsh/`, `work/`, Docker-файлы, `server.json`,
   workflow публикации и релиза; вычистить их из `pyproject.toml`, `marketplace-connector`,
   CI и тестов. Тесты снова зелёные.
3. **Переименовать** проект в `ru-shop-search`: имя в `pyproject.toml`, ссылки на репо,
   README. README переписать коротко и по-русски: что это, как поставить, какие магазины.
   CHANGELOG апстрима оставить как историю, свою запись начать сверху.
4. **Обвязка плагина.** Сначала сверь по актуальной документации Claude Code (агент
   `claude-code-guide` или context7) формат `plugin.json`, `.mcp.json`, переменные
   `${CLAUDE_PLUGIN_ROOT}` и `${CLAUDE_PLUGIN_DATA}`, способ валидации плагина. Сервер
   запускается через `uv run --directory ${CLAUDE_PLUGIN_ROOT} marketplace-mcp`. Проверка:
   плагин грузится в `claude` с `--plugin-dir`, список инструментов виден.
5. **Браузер.** Скрипт запуска выделенного профиля на macOS (`scripts/`), CDP на
   `127.0.0.1`, allowlist хостов. Проверь, что делает `CHROME_STEALTH` в апстриме, и реши,
   нужен ли он. Проверка: Ozon-поиск через `fetch` из вкладки отдаёт товары.
6. **Магазины по одному** в порядке: WB, Маркет, Ozon, DNS, Ситилинк, М.Видео, Детмир,
   Лэмода, ВсеИнструменты, Regard, Никс, Холодильник, AliExpress, Pepper. На каждый:
   офлайн-тесты на сохранённой фикстуре, затем один живой смоук-запрос.
7. **Авито.** Сначала один запрос проверяет, снят ли флаг с домашнего IP. Снят: коннектор,
   фильтры, карточка, `avito_evaluate`. Не снят: делай на фикстурах, живую проверку
   помечай «не проверено», не долби.
8. **`compare` и `price_history`.** Сопоставление через `identity.py`, SQLite-снимки,
   история WB и DNS. Тест на пару заведомо одинаковых товаров из двух магазинов.
   Там же поправить статус источника: `_source_error` сейчас пишет `blocked` на любой
   `transport_down`, в том числе на 5xx и сбой вкладки, а блок — только отказ магазина.
9. **Скиллы.** Три сценария из раздела «Что уже решено». Проверка: на каждый по одному
   прогону в свежей сессии с установленным плагином.
10. **Приёмка.** Полный офлайн-набор, ruff, mypy, живая матрица одним скриптом (по запросу
    на магазин, с паузами), обновлённые `docs/LIVE_STATUS.md` и этот файл.

## Отступления от плана и их причины

- **MCP-сервер объявлен в `plugin.json`, а не в `.mcp.json`.** Файл `.mcp.json` в корне
  репозитория Claude Code читает ещё и как проектный конфиг, когда `claude` запущен в этом
  каталоге; там `${CLAUDE_PLUGIN_ROOT}` не задан, и сервер висит с предупреждением
  «Missing environment variables». Поле `mcpServers` в `plugin.json` документация
  допускает как равноправное.
- **Удержание вкладки с капчей из апстрима вырезано** (`browser_handoff`,
  `compare_browser_snapshot`, `vision_policy`). Оно держало вкладку с капчей и звало
  повторить запрос после её прохождения, а правила требуют стопа на первом отказе. Пройти
  капчу самому в окне профиля по-прежнему можно, после этого стоп снимает
  `marketplace-mcp resume <магазин>`.
- **Скиллы апстрима удалены на шаге 4, а не на шаге 9.** Плагин подхватывает `skills/`
  автоматически, а старые скиллы описывали инструменты коннекторов, которых на сервере
  плагина больше нет. Три новых скилла появятся на шаге 9.

- **403-страница антибота Ozon не считается отказом, если вкладка сама ушла на 200.**
  На свежем профиле первый заход на `www.ozon.ru` получает `403 Antibot Challenge Page`,
  через 1–2 с страница сама перезагружается в 200 (проверено 2026-09-27). Мы в это
  время ничего не шлём и ничего не нажимаем. `open_page(..., challenge_grace_s=12)`
  ждёт этот переход; не дождался — стоп, как при любом отказе. Без выдержки Ozon
  останавливался бы на каждом новом профиле.
- **HTTP-уровень Ozon убран.** Он всегда получал 307 `__rr` и 403, то есть каждый вызов
  начинался с отказа, а после него шёл второй запрос через вкладку.
- **`CHROME_STEALTH` оставлен включённым.** Это не маскировка отпечатка: он открывает
  вкладки в фоне и прячет окно Chrome, как ⌘H, чтобы оно не выскакивало поверх работы.
  Окно настоящее, не headless; Ozon со скрытым окном антибот проходит.
- **Профиль Chrome лежит в `${CLAUDE_PLUGIN_DATA}/chrome-profile`**, а не в
  `~/Library/Application Support/Chrome-Scraping` апстрима: куки должны жить только в
  каталоге данных плагина. `CHROME_CDP_HOST` удалён, CDP только на `127.0.0.1`.
- **Поиск WB: только v18 с токеном, v9 и `search-goods` убраны.** v9 без токена
  отвечает 403, а для стоп-правила это отказ: каждый поиск начинался бы со стопа WB.
  `search-goods` отдаёт снятые с продажи товары без цен. Пробовать v9 с токеном не
  стали: v18 с токеном уже работает, лишний эндпоинт — лишний шанс на отказ.
- **Запасной путь через httpx для `card.wb.ru` и `catalog.wb.ru` сужен.** Апстрим
  повторял запрос через httpx после любого неудачного ответа, в том числе после 403.
  Теперь повтор только когда `curl_cffi` не получил статуса вообще (обрыв, таймаут).
  Кроме того, любой запрос WB, включая зеркала отзывов, сначала проверяет стоп.
- **Маркет: карточка только по ссылке `/card/`, голый id отклоняется до запроса.**
  2026-09-27 `/product/<id>` ответил 302 на `/showcaptcha` с первого раза, то есть
  каждая карточка по id означала бы стоп Маркета. Апстрим считал такие 302 «пустым
  временным сбоем» и повторял их дважды; теперь повторяется только 302 без `Location`.
- **DNS идёт через вкладку профиля, а не через HTTP с кукой `qrator_jsid2`.** Сравнивали
  апстримный `dns-connector` (страница во вкладке, цены из DOM) и `SZhukovWork/dns-shop-mcp`
  (Playwright с отдельным headless Chromium добывает куку, дальше HTTP и `/ajax-state/`).
  Вкладка работает вживую (2026-09-27): Qrator отвечает свежему профилю 401 со скриптом, и
  через ~2 с страница сама перезагружается в 200 с ценами; следующие запросы идут сразу в
  200. Путь SZhukovWork тянет Playwright и второй браузер, а HTTP с протухшей кукой снова
  получает 401, то есть стоп. Код SZhukovWork не переносился. Эндпоинт истории цен DNS
  для шага 8 посмотрим у него же.
- **401 Qrator получает ту же выдержку, что 403 Ozon.** `open_page(...,
  challenge_grace_s=12)` ждёт, пока страница с 401 или 403 сама уйдёт в 200; мы в это время
  ничего не шлём. Коммиченный тест ядра запрещал выдержку для 401, его пришлось изменить.
  401/403, который не ушёл в 200 за 12 с, по-прежнему стоп. 429 ждёт выдержку только у
  Ситилинка, у остальных это стоп сразу (см. ниже).
- **Запрос HTTP-магазина вынесен в ядро** (`mcp_core.transport.impersonated`).
  `impersonated_get` и `impersonated_post` отдают статус и `Location`, чтобы коннектор сам
  отличил капчу от сбоя. `shop_request` добавляет паузу из `Pacer` и стоп-правило: на
  401/403/418/429 магазин встаёт на 30 минут, повторяются один раз только обрыв сети и
  502/503/504. Этим путём уже ходит Детмир, дальше пойдут новые HTTP-магазины.
  418 добавлен в отказы, потому что так отвечает DDoS-Guard Детмира.
- **У Детмира появился поиск, хотя апстрим свой удалил.** Апстрим искал через API, а тот
  фильтр по тексту игнорирует: на «лего» приходили подгузники. Теперь поиск читает
  страницу сайта `/search/results/`, в ней `window.appData` с первой страницей выдачи
  (проверено вживую 2026-09-27). Ловушка осталась в другом виде: без совпадений сайт
  отдаёт сотни популярных товаров. Такую выдачу коннектор узнаёт по пустым подсказкам
  сайта и отсутствию слов запроса в названиях и отдаёт пустой список с `no_match`.

- **Лэмода читает страницы сайта, а не вкладку и GraphQL.** Апстрим искал через вкладку
  Chrome, а карточку брал из GraphQL. С домашнего адреса страницы поиска и товара
  отвечают на HTTP 200, и в них JSON со всеми данными (проверено 2026-09-27). GraphQL
  отдаёт цену без акции сайта: 11 199 ₽ там, где любой покупатель платит 8 063 ₽. Акция
  идёт без промокода и до срока, поэтому входит в `price_rub`, а срок — в `promo_until`.

## Базовая линия апстрима

Снято на `c17bd36` до правок, 2026-09-27, с `npm ci` (jsdom для DOM-тестов):
`pytest -m "not live and not cdp"` 1850 passed, 1 skipped; покрытие ветвей 81,89%;
`mypy` чисто; `ruff` чисто (скрипты проб из `docs/handoff/probes` исключены из проверки).

## Готово, когда

- Офлайн-тесты, `ruff` и `mypy` зелёные, покрытие не ниже порога CI апстрима (70%).
- Плагин ставится из локального каталога и поднимает один MCP-сервер без ручных шагов,
  кроме запуска браузерного профиля.
- `search` по запросу «rtx 5070» отдаёт товары с ценой и ссылкой минимум из WB, Маркета,
  Ozon, DNS, Ситилинка и М.Видео; по остальным магазинам статус в `docs/LIVE_STATUS.md`
  честный: работает, не работает и почему, не проверено.
- `compare` сводит одну и ту же модель из разных магазинов и показывает уверенность.
- `price_history` отдаёт историю WB и DNS и свои снимки.
- `avito_evaluate` работает на фикстурах; живой статус записан.
- Три скилла срабатывают на свои фразы в свежей сессии.
- В репозитории нет персональных данных, токенов и кук: `rg` по `x_wbaas_token`,
  `qrator_jsid2`, телефонам и именам продавцов в фикстурах пуст.

## Проверка своих действий

- После каждой задачи: тесты, ruff, mypy. Красное не переносится в следующую задачу.
- Живой запрос нужен для каждого утверждения «магазин работает». Результат пиши в
  `docs/LIVE_STATUS.md` с датой: что запросили, что пришло, сколько товаров, была ли цена.
- Фикстуры сохраняй из живых ответов, но перед сохранением вычищай персональные данные.
  Апстрим на этом прокалывался трижды.
- Для сложных задач (новый коннектор, скоринг) полезен независимый ревьюер-субагент,
  которому дают исходную постановку из этого файла, а не твой план. Модель субагенту
  выбирай явно: механике хватит дешёвой.

## Жёсткие ограничения

- **Темп.** Не чаще запроса в 3–5 секунд на магазин, серии живых запросов короткие. На
  первый отказ (403, 429, 498 без восстановления, капча, «доступ ограничен») магазин
  останавливается, повторов в цикле нет. Флаг на Авито уже получен именно так.
- **Капчи не решать**, ни руками, ни сервисами, ни кликом по чекбоксу. Капча = стоп и
  запись в статус. Дмитрий может пройти её сам в видимом окне, если захочет.
- **Никаких логинов** и личных аккаунтов, никаких сообщений продавцам, отзывов, корзин.
- **VPS** только для сравнительных проб; туннель закрывать сразу после. Роутер, mihomo и
  xkeen не трогать.
- **Git:** работа в ветке `plugin/bootstrap`. Push, PR, теги, релизы и любые публикации
  только по прямой просьбе Дмитрия. Локальные коммиты делай, если это разрешено в
  постановке сессии. Новые ветки: `git switch -c <имя> <база> --no-track`.
- **Секреты и персональные данные** не попадают в репозиторий, логи и чат. Токен WB и
  куки живут только в `${CLAUDE_PLUGIN_DATA}` или кэше вне git.
- **Зависимости:** не брать `undetected-chromedriver`, `hrequests`, `playwright-stealth`,
  `nodriver` (AGPL), облачные браузеры и сервисы, которым уходят запросы.
- Тяжёлые процессы (браузеры, туннели) закрывать после проверки и убеждаться через `pgrep`.

## Язык

Документация, комментарии к решениям, коммиты и статус по-русски. Идентификаторы, имена
инструментов и существующие английские комментарии апстрима остаются как есть.
- **Ситилинк идёт через вкладку профиля, а не через решатель `_pcl` и GraphQL.**
  `SZhukovWork/citilink-mcp` на 429 со страницей «Загрузка...» решает JS-проверку на
  Python и повторяет запрос, то есть шлёт второй запрос после отказа. Вкладка проходит ту
  же проверку сама: 429 через 1,5 с перезагружается в 200 (проверено 2026-09-27), мы в это
  время ничего не шлём. Поэтому `open_page` получил параметр `challenge_statuses`, и
  Ситилинк передаёт в него 429 вместе с 401/403. У остальных магазинов 429 по-прежнему
  стоп сразу. Выдача читается из плиток внутри `ProductListLayout`: на «ничего не
  найдено» сайт показывает рекомендации с ценами в другом блоке. Карточка читает
  `productBase` из `__NEXT_DATA__`, из вкладки уходят только поля товара; куки, адрес
  посетителя и токены из того же JSON наружу не попадают. Клубная цена в `price_rub` не
  идёт. Код SZhukovWork не переносился.
- **Карточка М.Видео идёт через вкладку, а не по HTTP.** По HTTP `/bff/pdp/info` и
  `/bff/location` отвечают 403, хотя `/bff/products` пускает (проверено 2026-09-27).
  Вкладка открывает страницу товара в 200 и читает schema.org `Product` (цена, наличие,
  рейтинг) и блок цены на странице (зачёркнутая цена). Отзывы из той же разметки наружу
  не уходят: в них имена покупателей. Бонусные рубли ценой не считаются. На запрос без
  совпадений `/bff/products` отвечает 204 без тела, это честный пустой ответ.

## Открытые вопросы

- Снят ли флаг Авито с домашнего IP.
- Как часто на деле нужен новый токен WB. Кэш держит его 30 ч, сайт обещает 36 ч;
  подтвердится только за несколько дней работы.
- Город для цен WB. Сейчас Москва (`-1257786`, как у сайта); другой город задаётся
  `WB_REGION`, список в `wb_connector/regions.py`.
- Город для цен DNS. Сайт выбирает его сам по IP, и это не Москва, в отличие от WB. Цены
  и наличие DNS зависят от города; `dns_search` и `dns_card` возвращают поле `city`, но
  менять город плагин пока не умеет. Нужно ли выбирать город, и какой?
- Разрешить ли для Ситилинка решатель `_pcl` на Python (как у SZhukovWork). Он даст путь
  по HTTP без Chrome, GraphQL и выбор города через `_space`, но каждый новый `_pcl`
  начинается с 429 и повторного запроса. Сейчас не используется; вкладка работает.
- Город для цен Ситилинка: сайт выбирает его по IP, как DNS, и это не Москва.
  `citilink_search` и `citilink_card` возвращают `city`.
- Выдержит ли `fetch` из вкладки Ozon серию запросов без нарастающих блоков.
- Считать ли цену по Ozon Карте обычной. Сейчас нет: она идёт рядом, как цена с Плюсом
  у Маркета, и в ранжирование не попадает. Карта бесплатная, но это банковский продукт,
  а не цена для любого покупателя. Вопрос не мелкий: плитка поиска Ozon другой цены не
  несёт, поэтому строки Ozon в `search` сейчас не ранжируются вовсе. Обычную цену
  отдаёт `card`, и скилл «найди дешевле» (шаг 9) должен звать его для строк Ozon.
- Выдержит ли Маркет серию запросов с паузой 3 с: проверено только 2 запроса подряд.
- Работает ли `t.me/s/pepperru` как источник Pepper без логина.
- `claude -p` из сессии агента не авторизуется: «OAuth session expired and could not be
  refreshed» (2026-09-27). `claude plugin …` и `claude mcp list` работают. Для проверки
  скиллов в свежей сессии (шаг 9) нужен рабочий вход, возможно, `claude` → `/login`.
